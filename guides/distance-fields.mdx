title: "Distance Fields and Lumen"
description: "Supply FRealtimeMeshDistanceField and FRealtimeMeshCardRepresentation to enable Lumen global illumination and ambient occlusion for procedural meshes."
---

Unreal Engine 5's **Lumen** global illumination system uses two complementary data structures to light meshes correctly without ray-marching every polygon:

- **Distance fields** — signed distance field volumes that Lumen uses for ambient occlusion (DFAO) and approximate reflections.
- **Card representations** — a set of planar projections ("cards") that Lumen uses to populate its surface cache for indirect lighting.

Procedureal meshes generated by RMC do not have these computed automatically at cook time, so you must supply them explicitly via `URealtimeMeshSimple`.

## When you need to set these

| Use case | Distance field needed? | Card representation needed? |
|----------|------------------------|------------------------------|
| Dynamic indirect lighting (Lumen GI) | No | Yes |
| Ambient occlusion via DFAO | Yes | No |
| Full Lumen surface cache (recommended) | Yes | Yes |
| Purely emissive or unlit meshes | No | No |
| Nanite meshes | Built into Nanite | Built into Nanite |

<Note>
If your project uses Lumen and your procedural meshes appear flat or do not receive indirect light correctly, supplying a card representation is the most important fix.
</Note>

## FRealtimeMeshDistanceField

Declared in `Mesh/RealtimeMeshDistanceField.h`, `FRealtimeMeshDistanceField` wraps a multi-mip sparse distance field volume. Construct it from a fully built `FDistanceFieldVolumeData`:

```cpp
#include "Mesh/RealtimeMeshDistanceField.h"
#include "DistanceFieldAtlas.h"   // FDistanceFieldVolumeData

// Build the distance field using Epic's offline builder tools,
// then wrap it for RMC.
FDistanceFieldVolumeData VolumeData = BuildDistanceField(MyMesh);
FRealtimeMeshDistanceField DistanceField(VolumeData);
```

Once constructed, check validity before uploading:

```cpp
if (DistanceField.IsValid())
{
    // Safe to set on the mesh
}
```

### Setting a distance field

Call `SetDistanceField` on the `URealtimeMeshSimple`. It accepts both move and const-ref overloads and returns a `TFuture<ERealtimeMeshProxyUpdateStatus>`:

```cpp
// Move overload — preferred when you no longer need the local copy
RealtimeMesh->SetDistanceField(MoveTemp(DistanceField)).Next(
    [](ERealtimeMeshProxyUpdateStatus Status)
    {
        // Notified when the render proxy is updated
    }
);
```

A Blueprint-callable overload accepts an `OnComplete` delegate:

```
RealtimeMesh → SetDistanceField(DistanceField, OnComplete)
```

### Clearing a distance field

```cpp
RealtimeMesh->ClearDistanceField();
```

### Reading the current distance field

```cpp
const FRealtimeMeshDistanceField& Current = RealtimeMesh->GetDistanceField();
bool bHasField = Current.IsValid();
```

## FRealtimeMeshCardRepresentation

Declared in `Mesh/RealtimeMeshCardRepresentation.h`, `FRealtimeMeshCardRepresentation` wraps an array of `FLumenCardBuildData` planar projections used to populate Lumen's surface cache.

Construct it from `FCardRepresentationData` produced by Epic's mesh card builder:

```cpp
#include "Mesh/RealtimeMeshCardRepresentation.h"
#include "MeshCardRepresentation.h"  // FCardRepresentationData

FCardRepresentationData CardData = BuildCardRepresentation(MyMesh);
FRealtimeMeshCardRepresentation CardRepresentation(CardData);
```

### Checking validity

```cpp
if (CardRepresentation.IsValid())
{
    // Has at least one card
}
```

### Setting a card representation

```cpp
RealtimeMesh->SetCardRepresentation(MoveTemp(CardRepresentation));
```

Blueprint variant:

```
RealtimeMesh → SetCardRepresentation(CardRepresentation, OnComplete)
```

### Clearing a card representation

```cpp
RealtimeMesh->ClearCardRepresentation();
```

### Reading the current card representation

This requires a lock context because the representation is held on the internal mesh data object:

```cpp
TSharedRef<RealtimeMesh::FRealtimeMeshSimple> MeshData = RealtimeMesh->GetMeshData();
RealtimeMesh::FRealtimeMeshReadScopeLock Lock(MeshData);
const FRealtimeMeshCardRepresentation* Card = RealtimeMesh->GetCardRepresentation(Lock);
if (Card && Card->IsValid())
{
    SIZE_T Bytes = Card->GetResourceSizeBytes();
}
```

## When to generate these structures

### At mesh creation time (recommended)

Building distance fields and card representations is computationally expensive. Whenever possible, generate them as part of your offline or load-time mesh generation step:

```cpp
void AMyActor::BeginPlay()
{
    Super::BeginPlay();

    URealtimeMeshSimple* RealtimeMesh =
        GetRealtimeMeshComponent()->InitializeRealtimeMesh<URealtimeMeshSimple>();

    // 1. Generate your procedural mesh geometry
    GenerateMeshData(RealtimeMesh);

    // 2. Build and assign distance field
    FRealtimeMeshDistanceField DF = BuildMyDistanceField();
    if (DF.IsValid())
    {
        RealtimeMesh->SetDistanceField(MoveTemp(DF));
    }

    // 3. Build and assign card representation
    FRealtimeMeshCardRepresentation CR = BuildMyCardRepresentation();
    if (CR.IsValid())
    {
        RealtimeMesh->SetCardRepresentation(MoveTemp(CR));
    }
}
```

### Lazily (deferred generation)

For large worlds where not every mesh is immediately visible, defer generation until the mesh first enters the view frustum:

```cpp
void AMyActor::OnMeshFirstVisible()
{
    if (!RealtimeMesh->GetDistanceField().IsValid())
    {
        Async(EAsyncExecution::ThreadPool, [this]()
        {
            FRealtimeMeshDistanceField DF = BuildMyDistanceField();
            AsyncTask(ENamedThreads::GameThread, [this, DF = MoveTemp(DF)]()
            {
                RealtimeMesh->SetDistanceField(MoveTemp(DF));
            });
        });
    }
}
```

## Memory and performance considerations

### Distance fields

- Stored as a multi-mip sparse volume. A 64³ voxel field at `uint8` precision is approximately 256 KB before compression.
- Uploaded to the GPU distance field atlas. Memory pressure here can cause Lumen quality degradation across the whole scene.
- Avoid regenerating every frame — distance fields are intended for static or slowly changing geometry.

### Card representations

- Each card is a small planar projection. A typical mesh needs 6–12 cards (one per face direction).
- Memory cost is low compared to distance fields.
- Lumen's surface cache re-captures cards when materials change. Modifying the card representation frequently forces re-captures and reduces Lumen quality.

<Warning>
If you set and clear `FRealtimeMeshDistanceField` frequently (for example, every frame), the distance field atlas can fragment and degrade Lumen performance for the entire scene. Only update distance fields when the mesh geometry actually changes substantially.
</Warning>

## Resource size helpers

Both structures expose helpers for memory profiling:

```cpp
// Distance field
FResourceSizeEx SizeEx;
DistanceField.GetResourceSizeEx(SizeEx);
SIZE_T DistanceFieldBytes = DistanceField.GetResourceSizeBytes();

// Card representation
FResourceSizeEx CardSizeEx;
CardRepresentation.GetResourceSizeEx(CardSizeEx);
SIZE_T CardBytes = CardRepresentation.GetResourceSizeBytes();
```

Use these in combination with `stat Memory` in the console to track Lumen-related memory usage from your procedural meshes.

## Serialization

Both structures support `FArchive` serialization via their `Serialize(FArchive& Ar, UObject* Owner)` methods. This means you can save pre-built distance fields and card representations to disk (for example, in a custom `UObject` asset) and load them at runtime, avoiding the build cost entirely in shipped builds.
